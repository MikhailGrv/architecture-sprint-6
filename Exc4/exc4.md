1. Проработайте реализацию osago-aggregator. Решите:
Сервис должен выдерживать 2.5 тыс. запросов единовременно + запас минимум 0.5 тыс.
Скрость ответа 60сек.
    1. Выбираем Server push, т.к. более простой Client pull может "заспамить" сетевые подключения ИС (информационной системы)
    2. client push реализуется на стороне API GateWay (APIGW), APIGW общается с osago-aggregator  по REST (двунапраленная связь). При этом osago-aggregator знает клиента от которого пришел запрос и при вызове APIGW указывает ответ для какого клиента. Для этого требуется хранить состояние.
    3. HPA для osago-aggregator 
    4. Хранение состояния в Redis как кэш. Состав хранимых данных: Клиент (от кого запрос), Страховая (куда направлен запрос), Датавремя (запроса), статус, датавремя последнего запроса.
    5. Каждый под osago-aggregator смотрит кэш запросов, если видит статус "в работе" и видит, что время пришло опроса (разница между текущем времем - последним опросом > Хсек && <60сек) - проставляет время опроса сейчас ("лайт" блокировка под себя опроса) - запрашивает данные у страховой. Если предоставлены данные делает вызов APIGW с информацией для клиента - проставляет статус выполнено. APIGW передает запрос клиенту
2. Требуется ли ему своё хранилище данных?
   да, состояние опроса (описано выше)

Однако, здесь может быть искажение данных на сотороне клиента и предоставление некорректных данных для офрмления. Если такой риск требуется устранить, то тогда предложения должны стримиться через Event-bus в core-app
   Также, возможен вариант, что core-app будет инициатором расчета - но зачем (требует обсуждения)?

7. В зависимости от выбранных средств интеграции подумайте, требуется ли где-то применение паттернов отказоустойчивости:
    Rate Limiting,
    Да, требуется. иначе можем получить неконтролируемый рост запросов и отказ в обслуживании.
    Circuit Breaker,
    Да, т.к. отказ osago-aggregator или client-info не должен сказываться на возможности оформить страховку core-app
    Retry,
    Да, для osago-aggregator при запросе предложений ОСАГО, попробовать отправить запрос несколько раз
    Timeout.
    Да, для osago-aggregator в случае, если не получен ответ более 60сек
